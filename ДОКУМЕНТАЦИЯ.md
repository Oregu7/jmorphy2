# Документация jmorphy2

## Обзор проекта

**jmorphy2** — это Java-порт библиотеки [pymorphy2](https://github.com/kmike/pymorphy2) для морфологического анализа русского и украинского языков. Проект предоставляет механизм лемматизации (приведения слов к нормальной форме), определения грамматических признаков и извлечения субъектов из текста. Основное применение — интеграция с Elasticsearch и Lucene в виде плагина анализатора.

---

## Структура модулей

Проект построен как Gradle multi-project и состоит из следующих модулей:

```
jmorphy2/
├── dawg/                    # Структура данных DAWG (Directed Acyclic Word Graph)
├── jmorphy2-core/           # Ядро морфологического анализатора
├── jmorphy2-dicts-ru/       # Словари для русского языка
├── jmorphy2-dicts-uk/       # Словари для украинского языка
├── jmorphy2-nlp/            # NLP-модуль: теггер, парсер, извлечение субъектов
├── jmorphy2-lucene/         # Интеграция с Apache Lucene
├── jmorphy2-elasticsearch/  # Плагин для Elasticsearch
├── jmorphy2-solr/           # Заготовка модуля для Apache Solr
└── benchmarks/              # JMH-бенчмарки производительности
```

## Модуль `dawg` — Структура данных DAWG

### Назначение

DAWG (Directed Acyclic Word Graph) — направленный ациклический граф слов, компактная структура данных для хранения словаря. Используется для эффективного поиска слов и их форм.

### Ключевые классы

| Класс | Описание |
|---|---|
| `DAWG` | Базовый класс для загрузки и навигации по графу из бинарного потока |
| `Dict` | Внутреннее представление словаря DAWG: массив юнитов с операциями follow/hasValue |
| `IntegerDAWG` | DAWG с целочисленными значениями (используется для оценки вероятностей P(t\|w)) |
| `PayloadsDAWG` | DAWG с произвольными payload-данными (Base64-декодирование). Поддерживает поиск похожих элементов с заменой символов (`similarItems`) |

### Принцип работы

1. Бинарный файл DAWG загружается в память как массив байтов
2. Каждый узел графа кодируется двумя числами: base (смещение) и check (индекс родителя)
3. Поиск осуществляется побайтовым перемещением по графу (метод `followByte` / `followBytes`)
4. Для `PayloadsDAWG` после ключа идёт разделитель `0x01`, за которым хранится payload в Base64
5. Поиск похожих слов (`similarItems`) учитывает карту замен символов — например, ё→е, и→й

## Модуль `jmorphy2-core` — Ядро анализатора

### Основные классы

#### `MorphAnalyzer`

Главный класс морфологического анализатора. Реализует паттерн Builder для конфигурации.

**Ключевые методы:**
- `parse(String word)` → `List<ParsedWord>` — полный морфологический разбор слова
- `normalForms(String word)` → `List<String>` — получение нормальных форм (лемм)
- `tag(String word)` → `List<Tag>` — получение грамматических тегов

**Алгоритм `parse()`:**

```
1. Слово приводится к нижнему регистру
2. Последовательно опрашиваются единицы анализа (AnalyzerUnit):
   - Если единица вернула результаты и terminate=true — цикл прерывается
   - Если единица вернула null — переход к следующей
3. Результаты дедуплицируются (по паре tag + normalForm)
4. Оценивается вероятность каждого разбора через ProbabilityEstimator
5. Результаты сортируются по убыванию score
```

**Порядок единиц анализа (по умолчанию):**

| # | Единица | terminate | score | Описание |
|---|---------|-----------|-------|----------|
| 1 | `DictionaryUnit` | true | 1.0 | Поиск слова в словаре (точное совпадение) |
| 2 | `NumberUnit` | true | 0.9 | Распознавание чисел |
| 3 | `PunctuationUnit` | true | 0.9 | Распознавание пунктуации |
| 4 | `RomanUnit` | false | 0.9 | Римские цифры |
| 5 | `LatinUnit` | true | 0.9 | Латинские слова |
| 6 | `KnownPrefixUnit` | true | 0.75 | Слова с известными приставками |
| 7 | `UnknownPrefixUnit` | true | 0.5 | Слова с неизвестными приставками (перебор) |
| 8 | `KnownSuffixUnit` | true | 0.5 | Предсказание по известным суффиксам |
| 9 | `UnknownUnit` | true | 1.0 | Фоллбэк для нераспознанных слов |

Параметр `terminate` означает: если эта единица нашла разбор, прервать цепочку. Однако поиск продолжается, если предыдущие единицы не дали результатов.

#### `Dictionary`

Загружает и хранит морфологический словарь в формате pymorphy2. Содержит:

- **Meta** (`meta.json`) — метаданные словаря: версия формата, язык, параметры компиляции
- **Paradigm[]** (`paradigms.array`) — массив парадигм словоизменения. Каждая парадигма — набор троек (suffix_id, tag_id, prefix_id)
- **WordsDAWG** (`words.dawg`) — DAWG со всеми словоформами, в payload хранятся (paradigmId, idx)
- **SuffixesDAWG[]** (`prediction-suffixes-N.dawg`) — DAWG суффиксов для предсказания (по одному на каждый paradigmPrefix)
- **String[] suffixes** (`suffixes.json`) — массив суффиксов
- **Tag[] gramtab** (`gramtab-opencorpora-int.json`) — массив грамматических тегов

**Формат словаря (файлы в `pymorphy2_dicts/`):**

```
meta.json                         — метаданные
grammemes.json                    — граммемы (грамматические категории)
gramtab-opencorpora-int.json      — таблица грамматических тегов
paradigms.array                   — бинарный файл парадигм
suffixes.json                     — массив суффиксов
words.dawg                        — DAWG словоформ
prediction-suffixes-0.dawg        — DAWG суффиксов (предсказание, префикс "")
prediction-suffixes-1.dawg        — DAWG суффиксов (предсказание, префикс "по")
prediction-suffixes-2.dawg        — DAWG суффиксов (предсказание, префикс "наиболее")
p_t_given_w.intdawg               — вероятности P(tag|word) для ранжирования
```

**Как работает разбор в `DictionaryUnit`:**

1. Слово ищется в `WordsDAWG` (с учётом замен символов, например ё→е)
2. Для каждой найденной словоформы извлекаются `paradigmId` и `idx`
3. По парадигме строится нормальная форма: `prefix + stem + suffix`
4. Строится грамматический тег из `gramtab`

#### `ParsedWord`

Результат морфологического разбора. Содержит:

- `word` — исходное слово
- `tag` — грамматический тег
- `normalForm` — нормальная форма (лемма)
- `foundWord` — слово, найденное в словаре (может отличаться при замене символов)
- `score` — оценка достоверности разбора

Метод `getLexeme()` возвращает все словоформы той же лексемы (парадигмы).

#### `Tag`

Грамматический тег — набор граммем. Имеет предопределённые категории:

| Категория | Константа | Примеры значений |
|-----------|-----------|------------------|
| Часть речи | `POST` | NOUN, VERB, ADJF, INFN... |
| Одушевлённость | `ANim` | anim, inan |
| Род | `GNdr` | masc, femn, neut |
| Число | `NMbr` | sing, plur |
| Падеж | `CAse` | nomn, gent, datv, accs, ablt, loct... |
| Вид | `ASpc` | perf, impf |
| Переходность | `TRns` | tran, intr |
| Лицо | `PErs` | 1per, 2per, 3per |
| Время | `TEns` | past, pres, futr |
| Наклонение | `MOod` | indc, impr |
| Залог | `VOic` | actv, pssv |
| Вовлечённость | `INvl` | incl, excl |

`Tag.Storage` — глобальное хранилище тегов и граммем, обеспечивающее уникальность и нормализацию.

#### `Grammeme`

Граммема — минимальная грамматическая единица. Имеет иерархию (родитель → потомок):

- `value` — краткое имя (например, `NOUN`)
- `parentValue` — имя родительской граммемы (например, `POST`)
- `russianValue` — название на русском языке
- `description` — описание

Метод `getRoot()` поднимается по иерархии до корневой граммемы.

#### `ProbabilityEstimator`

Оценивает вероятность P(tag|word) для ранжирования разборов. Использует `IntegerDAWG` с файлом `p_t_given_w.intdawg`. Ключ имеет формат `слово:тег`, значение — частота, нормализованная делением на 1 000 000.

#### `Resources`

Загружает языковые ресурсы из classpath:
- `char_substitutes.txt` — карта замен символов (ё→е, и→й и т.д.)
- `known_prefixes.txt` — список известных приставок (по-, наи-, наиболее- и т.д.)

### Единицы анализа (AnalyzerUnit)

Все единицы наследуются от абстрактного класса `AnalyzerUnit`. Каждый юнит:
- Реализует метод `parse(String word, String wordLower)` → `List<ParsedWord>`
- Имеет флаг `terminate` — прерывать ли цепочку при успехе
- Имеет `score` — базовый вес разборов

**`DictionaryUnit`** — точный поиск в словаре. Использует `WordsDAWG.similarWords()` для поиска с заменой символов.

**`KnownSuffixUnit`** — предсказание по суффиксу. Алгоритм:
1. Отбрасывает слишком короткие слова (< 4 символов)
2. Для каждого известного префикса и суффикса (от длинного к короткому, макс. 5 символов)
3. Ищет суффикс в `SuffixesDAWG`
4. Если суффикс найден — строит разбор по парадигме
5. Score нормализуется по общей частоте суффиксов для данного префикса

**`KnownPrefixUnit`** — разбор слов с известными приставками. Отделяет приставку и передаёт остаток слова в `DictionaryUnit`.

**`UnknownPrefixUnit`** — перебор всех возможных приставок для неизвестных слов.

**`NumberUnit` / `PunctuationUnit` / `RomanUnit` / `LatinUnit`** — регулярные выражения для распознавания чисел, пунктуации, римских и латинских слов.

**`UnknownUnit`** — фоллбэк, возвращает слово с тегом UNKN.

## Модуль `jmorphy2-nlp` — Обработка естественного языка

### Компоненты

#### `SimpleTagger`

Теггер — назначает грамматические теги последовательности токенов. Работает по правилам (Ruleset):

1. Токены инициализируются с граммемой `UNKN`
2. Применяются правила для редукции (например, союзы, предлоги)
3. Если правило не сработало — слово разбирается через `MorphAnalyzer`
4. Для каждого разбора строится дерево (Node)
5. Результаты сортируются по score

Встроенные правила распознают союзы (а, и, но) и предлоги (без, в, для, до, за, из, к, на, над, о, от, по, при, про, с, у, через...).

#### `SimpleParser`

Парсер — строит синтаксическое дерево из размеченных токенов. Использует:
- `Tagger` — для разметки токенов
- `Ruleset` — набор правил для построения дерева
- `threshold` — порог для ограничения числа вариантов (по умолчанию 100)

Фильтрует граммемы по продуктивности: оставляет только Number и Case для согласования.

#### `SubjectExtractor`

Извлекатель субъектов — выделяет подлежащее и ключевые слова из предложения. Конфигурируется строкой правил:
- `+NOUN,Nomn` — включить извлечение для существительных в именительном падеже
- `-PREP` — отключить для предлогов
- `NOUN,Nomn` — критерий субъекта

Алгоритм:
1. Текст разбирается парсером в синтаксическое дерево
2. Дерево обходится рекурсивно
3. Листовые узлы проверяются на соответствие критериям
4. Слова нормализуются (приводятся к начальной форме) или оставляются как есть

## Модуль `jmorphy2-lucene` — Интеграция с Lucene

### Компоненты

#### `Jmorphy2Analyzer`

Готовый Lucene Analyzer, объединяющий:
1. `StandardTokenizer` — токенизация
2. `LowerCaseFilter` — приведение к нижнему регистру
3. `Jmorphy2StemFilter` — лемматизация с фильтрацией служебных слов (NPRO, PREP, CONJ, PRCL, INTJ)

#### `Jmorphy2StemFilter`

Lucene TokenFilter для лемматизации. Для каждого токена:
1. Вызывает `MorphAnalyzer.parse()`
2. Фильтрует разборы по `includeTags` / `excludeTags`
3. Выдаёт уникальные нормальные формы как отдельные токены
4. Первая лемма получает positionIncrement=1, остальные — positionIncrement=0 (синонимы)

Это позволяет находить документы по любой форме слова.

#### `Jmorphy2SubjectFilter`

Lucene TokenFilter для извлечения субъектов. Накапливает токены (до `maxSentenceLength`), затем передаёт их в `SubjectExtractor` и выдаёт только токены-субъекты.

#### Фабрики (`*Factory`)

Lucene-совместимые фабрики для конфигурации через SPI:
- `Jmorphy2StemFilterFactory` — создаёт `Jmorphy2StemFilter` из конфигурации
- `Jmorphy2SubjectFilterFactory` — создаёт `Jmorphy2SubjectFilter`
- `LuceneFileLoader` — загрузчик ресурсов через Lucene `ResourceLoader`

## Модуль `jmorphy2-elasticsearch` — Плагин для Elasticsearch

### Архитектура плагина

```
┌─────────────────────────────────────────────────────┐
│                  Elasticsearch                       │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │    AnalysisJmorphy2Plugin                      │  │
│  │    (Plugin implements AnalysisPlugin)           │  │
│  │                                                │  │
│  │  getTokenFilters():                            │  │
│  │    "jmorphy2_stemmer" → Jmorphy2StemTF         │  │
│  │    "jmorphy2_subject" → Jmorphy2SubjectTF      │  │
│  └──────────────┬─────────────────────────────────┘  │
│                 │                                     │
│  ┌──────────────▼─────────────────────────────────┐  │
│  │    Jmorphy2Service                              │  │
│  │    (синглтон, кэширует анализаторы)             │  │
│  │                                                │  │
│  │  morphAnalyzers: ConcurrentHashMap              │  │
│  │  subjectExtractors: ConcurrentHashMap           │  │
│  │                                                │  │
│  │  getMorphAnalyzer(lang, substitutes, cache)     │  │
│  │  getSubjectExtractor(lang, rules, ...)          │  │
│  └──────────────┬─────────────────────────────────┘  │
│                 │                                     │
│  ┌──────────────▼─────────────────────────────────┐  │
│  │    CachingMorphAnalyzer                         │  │
│  │    (MorphAnalyzer + Caffeine cache)             │  │
│  └────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### Ключевые классы

#### `AnalysisJmorphy2Plugin`

Точка входа плагина. Реализует интерфейс `AnalysisPlugin`. Регистрирует два token filter:
- `jmorphy2_stemmer` — лемматизация
- `jmorphy2_subject` — извлечение субъектов

#### `Jmorphy2Service`

Сервис управления экземплярами анализаторов. Работает на уровне индексов (indices), а не отдельных шардов. Кэширует:
- `MorphAnalyzer` по ключу (язык, substitutesPath, cacheSize)
- `SubjectExtractor` по составному ключу

Загрузка словарей:
1. Сначала ищет словари на файловой системе: `{jmorphy2Dir}/{lang}/pymorphy2_dicts/`
2. Если не найдено — загружает из classpath (встроенные словари из jmorphy2-dicts-ru/uk)

Путь к словарям настраивается через `indices.analysis.jmorphy2.dictionary.location` (по умолчанию: `jmorphy2`).

#### `CachingMorphAnalyzer`

Обёртка над `MorphAnalyzer` с LRU-кэшем на Caffeine. Кэширует результаты `parse()` для ускорения повторных запросов. Размер кэша задаётся параметром `cache_size` (по умолчанию 10000).

#### `Jmorphy2StemTokenFilterFactory`

Фабрика token-фильтра для Elasticsearch. Создаёт `Jmorphy2StemFilter` с параметрами:
- `lang` — язык (обязательный, "ru" или "uk")
- `char_substitutes_path` — путь к файлу замен символов
- `cache_size` — размер кэша (по умолчанию 10000)
- `include_tags` — включить только слова с этими тегами
- `exclude_tags` — исключить слова с этими тегами

#### `Jmorphy2SubjectTokenFilterFactory`

Фабрика фильтра субъектов. Дополнительные параметры:
- `tagger_rules_path` — путь к правилам теггера
- `parser_rules_path` — путь к правилам парсера
- `extract_rules_path` — путь к правилам извлечения
- `tagger_threshold` / `parser_threshold` — пороги
- `max_sentence_length` — максимальная длина предложения

### Конфигурация в Elasticsearch

Пример настройки анализатора:

```json
{
  "settings": {
    "analysis": {
      "filter": {
        "jmorphy2_stem": {
          "type": "jmorphy2_stemmer",
          "lang": "ru",
          "exclude_tags": "NPRO PREP CONJ PRCL INTJ"
        }
      },
      "analyzer": {
        "text": {
          "tokenizer": "standard",
          "filter": ["lowercase", "jmorphy2_stem"]
        }
      }
    }
  }
}
```

Пример извлечения субъектов:

```json
{
  "settings": {
    "analysis": {
      "filter": {
        "jmorphy2_subj": {
          "type": "jmorphy2_subject",
          "lang": "ru",
          "tagger_rules_path": "jmorphy2/ru/tagger_rules.txt",
          "parser_rules_path": "jmorphy2/ru/parser_rules.txt",
          "extract_rules_path": "jmorphy2/ru/extract_rules.txt"
        }
      }
    }
  }
}
```

## Поток данных (Data Flow)

### Морфологический разбор слова

```
"теплые" (входное слово)
       │
       ▼
  MorphAnalyzer.parse()
       │
       ├─► DictionaryUnit.parse()
       │    └─► WordsDAWG.similarWords("теплые", {ё→е})
       │         └─► Найдено: paradigmId=X, idx=Y
       │              └─► Tag: "ADJF Qual neut plur nomn"
       │              └─► NormalForm: "тёплый"
       │
       ├─► (terminate=true, разбор найден — прерываем цепочку)
       │
       ▼
  filterDups() — удаление дубликатов
       │
       ▼
  estimate() — оценка вероятностей P(tag|word)
       │
       ▼
  sort() — сортировка по score
       │
       ▼
  [ParsedWord("теплые", ADJF.., "тёплый", "теплые", 0.95)]
```

### Путь токена через Elasticsearch-плагин

```
Документ: "купить теплые перчатки"
       │
       ▼
  StandardTokenizer → ["купить", "теплые", "перчатки"]
       │
       ▼
  LowerCaseFilter → ["купить", "теплые", "перчатки"]
       │
       ▼
  Jmorphy2StemFilter (exclude: NPRO PREP CONJ PRCL INTJ)
       │
       ├─ "купить" → parse() → INFN → normalForm="купить" ✓ (не исключён)
       ├─ "теплые" → parse() → ADJF → normalForm="тёплый" ✓
       ├─ "перчатки" → parse() → NOUN → normalForm="перчатка" ✓
       │
       ▼
  Выходные токены: ["купить", "тёплый", "перчатка"]
  (position increments: [1, 1, 1])
```
